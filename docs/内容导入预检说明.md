# 旧站博客内容导入预检

该预检工具仅扫描旧站抓取的 DOCX 文件并生成 JSON 清单；不会写入 MySQL、不会移动图片或视频、不会修改源文件，也不会发布文章。

当前纳入范围：

- `新闻动态/公司新闻`；
- `新闻动态/行业新闻`；
- `相关案例`；
- `研发成果`；
- `应用技术`。

`新建文件夹`被明确排除，待业务确认用途后再决定是否纳入。

在仓库根目录运行：

```powershell
python scripts/content_preflight.py
```

默认生成 `docs/content-import-preflight.json`，并同时生成 `docs/content-import-review-list.md`。前者包含每篇文章的来源文件、分类、旧站链接、识别到的日期、嵌入媒体、提及的视频、正文预览、哈希和待人工处理的警告；后者仅列出缺少来源链接或原发布时间的文章，便于逐项补充。导出文件中的“收藏时间”会单列为 `export_captured_dates`，绝不会被自动当成原发布时间；`candidate_source_dates` 也只是待人工确认的候选日期。

视频仍保留在抓取目录的根部。工具通过“文章正文是否出现完整视频文件名”建立候选关联；未匹配的视频会列入 `unmatched_video_filenames`，由人工确认后再建关联。

对于 DOCX 中没有候选原发布时间、但已有旧站 URL 的文章，可运行：

```powershell
python scripts/fetch_legacy_publication_dates.py
python scripts/content_preflight.py
```

第一个命令会读取旧站公开页面中的 `article:published_time` 或 JSON-LD `datePublished`，写入 `docs/legacy-publication-date-fetch.json`；第二个命令将其写回预检报告的 `legacy_page_published_at` 字段，并从待补日期清单中移除已核验项目。

在预检报告被确认前，不能执行批量入库。后续实际导入必须将文章以 `DRAFT` 状态写入，并保留原始文件路径、旧站 URL、DOCX 哈希和内容哈希。同一篇文章可同时关联多个分类，其中一个为主分类，其他关联用于在不同栏目展示。

## 草稿导入包与样本预览

预检完成后，可运行：

```powershell
python scripts/build_content_draft.py
```

命令会生成 `docs/content-import-draft/manifest.json`、哈希去重后的图片资源和每个主分类一篇的 HTML 样本预览。该步骤不会写入数据库、不会移动原始 DOCX 或视频。确认样本内容后，批量导入器才会把 `manifest.json` 中的文章以草稿状态写入数据库。
