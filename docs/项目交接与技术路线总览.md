# 奥飞新材官网重构：项目交接与技术路线总览

更新日期：2026-07-19；适用范围：`alfy-site` 当前工作区。

## 1. 项目目的与公司内容边界

本项目为湖南奥飞新材料有限公司的新一代企业官网与内容管理后台。一期的目标是：以品牌展示、气凝胶及复合产品目录、行业应用方案、标杆案例、技术可信度和商务询盘为核心，提供可由公司维护的 CMS 后台。

已确认的站点导航与前端路由：`/`、`/products`、`/applications`、`/technology`、`/news`、`/cooperation`、`/about`。其中产品、应用场景、案例和新闻必须是独立内容实体，不以静态页面或文章替代。

可作为内容导入/核对来源的材料位于：

- `docs/奥飞新材｜新一代气凝胶及其复合产品技术  20260715(1).pdf`
- `docs/奥飞网站/`：历史官网文章、研发成果与应用技术的导入源
- `docs/奥飞新材官网详细设计方案与API设计思路.md`
- `docs/api-contract.md`

注意：产品性能参数、技术指标、客户名称/地点/效果、合作伙伴 Logo、与中南大学等机构的合作表述，都必须经公司确认和授权后才可发布。现有 mock 文案、历史文章或原型图不代表自动获得公开授权。

## 2. 当前仓库与技术架构

```text
alfy-site/
├─ alfy-api/      Spring Boot 3 后端，Java 25，MySQL，Flyway，MyBatis-Plus
├─ alfy-web/      Nuxt 前端初版（由前端同学负责，当前仍主要使用 mock）
└─ docs/          产品资料、接口契约、导入源、交接文档
```

后端技术路线：

1. Spring Boot REST API，统一前缀 `/api/v1`；
2. MySQL 数据库，所有结构变化通过 Flyway `V1` 至 `V10` 管理；禁止修改已执行迁移；
3. MyBatis-Plus 负责持久化、分页、逻辑删除与部分乐观锁；
4. Spring Security + Bearer JWT 保护后台；公开读取接口无需登录；
5. 媒体通过受控公开地址读取，只有被已发布文章、产品、场景或案例引用的素材可公开；
6. HTML 正文使用 Jsoup 清洗，后台写操作记录 `admin_operation_log`；
7. 内容生命周期：`DRAFT -> PUBLISHED -> OFFLINE`，只有 `PUBLISHED` 可经公开 API 返回。

统一成功返回：`{ "code": 0, "message": "success", "data": ... }`；列表 `data` 为 `{records,total,page,size}`。

## 4. 已实现业务闭环

```text
管理员登录
  -> 创建产品分类 / 场景 / 产品 / 案例（草稿）
  -> 编辑并保存 version
  -> 发布分类、场景、产品、案例
  -> /api/v1/public/** 仅返回已发布内容
  -> Nuxt 前端读取并渲染
```

### 4.1 请求与安全数据流

```text
浏览器 / Nuxt SSR
     │ GET /api/v1/public/**（无 Token）
     ▼
Public Controller → Public Service → MyBatis-Plus → MySQL
     │                         │
     │                         └─ 状态必须为 PUBLISHED
     ▼
统一 ApiResponse

后台管理端
     │ POST /admin/auth/login
     ▼
AdminAuthService → BCrypt 校验 admin_user → 签发 access/refresh token
     │
     └─ Bearer access token → JwtAuthenticationFilter → 管理员 CRUD
                                                  │
                                                  └─ admin_operation_log
```

### 4.2 发布顺序与可见性

| 内容 | 创建默认状态 | 发布前校验 | 公开可见条件 |
|---|---|---|---|
| 产品分类 | 启用（`status=1`） | 无发布动作 | 未删除且启用 |
| 场景 | `DRAFT` | 名称、slug、摘要 | `PUBLISHED` |
| 产品 | `DRAFT` | 名称、slug、摘要，分类启用 | `PUBLISHED` |
| 案例 | `DRAFT` | 标题、slug、摘要，场景已发布 | 案例与所属场景均 `PUBLISHED` |
| 新闻 | `DRAFT` | 标题、slug、正文、至少一个分类 | `PUBLISHED` |

关键约束：产品发布前分类必须启用；案例发布前所属场景必须已发布；删除分类前不能仍有产品；更新时必须携带详情返回的 `version`。

## 5. 本地运行与验证

后端目录：`alfy-api`。本地 MySQL 数据库会在启动/测试时自动执行 Flyway。

```powershell
cd D:\Projects\alfy-site\alfy-api
.\mvnw.cmd test -q
```

目前数据库已验证到 V10。测试可正常通过；日志会提示当前 MySQL 9.4 高于 Flyway 已测试的 MySQL 8.1，这不是本次迁移失败，但生产部署前应评估 Flyway/数据库版本兼容性。

管理员表为空时，可在首次启动前设置 `ALFY_INITIAL_ADMIN_USERNAME` 和 `ALFY_INITIAL_ADMIN_PASSWORD` 来创建本地管理员；该账号写入数据库并非临时值。不得将生产密码或 JWT 密钥提交到仓库。
