# 奥飞新材官网后端数据库表结构说明

更新日期：2026-07-19；当前 Flyway 版本：V10。数据库为 MySQL，主要业务表默认有 `created_at`、`updated_at`，内容主表通常有逻辑删除字段 `deleted`。

## 通用约定

- `id`：`BIGINT UNSIGNED` 主键；
- `deleted=1`：逻辑删除，默认查询不返回；
- 内容状态：`DRAFT` 草稿、`PUBLISHED` 已发布、`OFFLINE` 下线；
- `version`：乐观锁，编辑请求必须带回详情读取的版本值；
- `cover_media_id`：关联 `media_asset.id`，公开 URL 为 `/api/v1/public/media/{id}`；
- 当前迁移未建立 MySQL 外键，关联完整性由服务层校验与业务流程保证。

## 认证与审计

| 表 | 用途 | 关键字段 |
|---|---|---|
| `admin_user` | 后台账号 | `username`（唯一）、`password_hash`、`role`、`status`、`last_login_at` |
| `admin_refresh_token` | 刷新令牌 | `admin_user_id`、`token_hash`（唯一）、`expires_at`、`revoked_at` |
| `admin_operation_log` | 后台操作审计 | `admin_user_id`、`action`、`target_type`、`target_id`、`detail`、`created_at` |

角色为 `SUPER_ADMIN` 或 `CONTENT_ADMIN`；刷新令牌在数据库中仅保存哈希。

## 媒体与新闻

| 表 | 用途 | 关键字段/关系 |
|---|---|---|
| `media_asset` | 上传的文件元数据 | 存储路径、原文件名、MIME、大小、校验值、上传人 |
| `article_category` | 新闻分类 | `code`（唯一）、`name`、`parent_id`、`sort_order`、`status` |
| `article` | 新闻正文 | `title`、`slug`（唯一）、`summary`、`content_html/text`、`cover_media_id`、发布/SEO/首页推荐字段、`version` |
| `article_category_relation` | 文章—分类多对多 | `article_id`、`category_id`、`sort_order` |
| `article_media` | 文章—媒体引用 | `article_id`、`media_id`、`usage`、`sort_order` |

文章保留 `category_id` 作为兼容/主分类字段，多分类以 `article_category_relation` 为准。

## 产品、应用与案例

| 表 | 用途 | 关键字段/关系 |
|---|---|---|
| `product_category` | 产品分类 | `name`、`slug`（唯一）、`summary`、`cover_media_id`、`sort_order`、`status`（1 启用/0 停用）、`version` |
| `product` | 产品内容 | `category_id`、`name`、`slug`（唯一）、`summary`、`content_html/text`、`cover_media_id`、`features_json`、`specifications_json`、状态、SEO、`version` |
| `application_scene` | 应用场景 | `name`、`slug`（唯一）、`slogan`、`summary`、`pain_point`、`solution`、正文、封面、状态、SEO、`version` |
| `case_project` | 项目案例 | `scene_id`、`title`、`slug`（唯一）、客户/地点、摘要、背景/需求/方案/实施/结果、正文、封面、状态、SEO、`version` |
| `product_scene_rel` | 产品—场景多对多 | `id`、`product_id`、`scene_id`、`sort_order`；`(product_id,scene_id)` 唯一 |
| `product_case_rel` | 产品—案例多对多 | `id`、`product_id`、`case_id`、`sort_order`；`(product_id,case_id)` 唯一 |

关系概览：

```text
product_category 1 ── N product
application_scene N ── N product      (product_scene_rel)
application_scene 1 ── N case_project
case_project N ── N product           (product_case_rel)
```

## 前端联调关注字段

- 产品卡片：`product.category_id` 对应分类 slug/名称；`features_json` 为字符串数组；
- 参数：`specifications_json` 是 JSON，允许为空；
- 场景：前端的 `key` 对应 `application_scene.slug`；
- 案例：前端展示分类/场景名时从 `case_project.scene_id` 获取场景；
- 图片：不直接写静态 URL；创建内容时记录 `cover_media_id`，公开接口再生成媒体 URL。

## 当前未建表的业务

技术能力、合作伙伴、单页（技术/合作/关于）、招聘、询盘、Banner 和首页配置尚未进入当前 V1-V10 数据库结构。相关信息架构见 `docs/api-contract.md`，后续从 V11 开始新增迁移。

## 字段级数据字典

以下字段按当前 V1-V10 实际迁移整理；未特别说明时 `id` 为自增 `BIGINT UNSIGNED`，`deleted` 为 `TINYINT`（0 正常、1 逻辑删除），`created_at/updated_at` 为 `DATETIME`。

### `admin_user`

| 字段 | 类型/是否为空 | 含义与使用规则 |
|---|---|---|
| `username` | `VARCHAR(50)`，非空、唯一 | 登录名；创建后不应作为展示名称使用 |
| `password_hash` | `VARCHAR(255)`，非空 | BCrypt 密码哈希；绝不返回给前端 |
| `role` | `VARCHAR(32)`，非空 | 实际授权使用 `SUPER_ADMIN` / `CONTENT_ADMIN`（数据库默认历史值为 `content_admin`） |
| `status` | `TINYINT`，非空 | 1 可登录，0 禁用 |
| `last_login_at` | `DATETIME`，可空 | 最后成功登录时间 |

索引：`uk_admin_user_username(username)`。

### `media_asset`

| 字段 | 类型 | 含义 |
|---|---|---|
| `media_type` | `VARCHAR(16)` | `IMAGE`、`VIDEO`、`DOCUMENT` |
| `storage_key` | `VARCHAR(512)` | 本地相对路径或对象存储 Key，不是公开 URL |
| `original_filename` | `VARCHAR(255)` | 原始文件名 |
| `mime_type`、`file_size`、`sha256` | 字符串/数值 | 文件类型、字节数、去重/审计校验值 |
| `width`、`height`、`duration_seconds` | 数值，可空 | 图片/视频的可选元数据 |
| `alt_text` | `VARCHAR(255)`，可空 | 无障碍替代文字 |

索引：`media_type`、`sha256`。仅有记录不代表可公开，必须被已发布内容引用。

### `article_category`、`article` 与关联表

`article_category`：`parent_id` 用于分类树；`code` 是唯一稳定标识；`status=1` 才是启用分类。

| `article` 字段 | 类型 | 前端/业务意义 |
|---|---|---|
| `category_id` | BIGINT，非空 | 主分类，兼容排序与编辑入口；多分类以关联表为准 |
| `title`、`slug` | VARCHAR(255)，非空、slug 唯一 | 标题和公开路径；历史数据已补 `article-{id}` 占位 slug |
| `summary` | VARCHAR(1000)，可空 | 新闻卡片摘要 |
| `content_html` / `content_text` | LONGTEXT | 清洗后的正文 / 搜索与审计用纯文本 |
| `cover_media_id` | BIGINT，可空 | 封面素材 |
| `author_name`、`source_url`、`source_file` | VARCHAR，可空 | 来源归档；`source_url` 建有前缀索引 |
| `content_hash` | CHAR(64) | 导入排重辅助字段 |
| `source_published_at` / `published_at` | DATETIME | 原始发布时间 / 本站实际发布时间 |
| `status` | VARCHAR(16) | DRAFT、PENDING_REVIEW、PUBLISHED、OFFLINE |
| `sort_order`、`is_featured` | INT/TINYINT | 一般排序及首页推荐标志 |
| `home_slot`、`home_sort_order` | VARCHAR(32)/INT | `NEWS_PRIMARY`、`NEWS_SECONDARY`、`NEWS_LIST` 等首页位置 |
| `seo_title`、`seo_description`、`seo_keywords` | VARCHAR | 页面 SEO |
| `version` | BIGINT | 后台编辑乐观锁 |

`article_category_relation(article_id, category_id)` 唯一，支持多分类；`article_media(article_id, media_id, usage_type)` 唯一，`usage_type` 可为 `COVER`、`INLINE`、`VIDEO`、`ATTACHMENT`。`content_import_record` 记录 DOCX 导入预检、导入、跳过或失败的来源哈希和警告。

### 产品分类与产品

| `product_category` 字段 | 类型 | 说明 |
|---|---|---|
| `name`、`slug` | VARCHAR(100)，非空；slug 唯一 | 分类名、用于产品筛选的 URL 参数 |
| `summary` | VARCHAR(1000)，可空 | 分类简介 |
| `cover_media_id` | BIGINT，可空 | 分类封面 |
| `sort_order` | INT | 小值在前 |
| `status` | TINYINT | 1 启用、0 停用；产品发布前必须为 1 |
| `version` | BIGINT | 分类后台编辑乐观锁 |

| `product` 字段 | 类型 | 说明 |
|---|---|---|
| `category_id` | BIGINT，非空 | 指向产品分类 |
| `name`、`slug` | VARCHAR(255)，非空；slug 唯一 | 产品名称、公开详情路径 |
| `summary`、`content_html`、`content_text` | VARCHAR/LONGTEXT | 卡片摘要、清洗正文、纯文本 |
| `cover_media_id` | BIGINT，可空 | 产品封面 |
| `features_json` | JSON，可空 | 字符串数组，如 `["轻薄","施工便利"]` |
| `specifications_json` | JSON，可空 | 公司确认后公开的结构化参数对象 |
| `status`、`is_featured`、`sort_order` | 状态/标记/排序 | 公开列表只读 `PUBLISHED` |
| `seo_*`、`version`、`published_at` | 同新闻语义 | SEO、乐观锁、本站发布时间 |

索引：分类公开列表使用 `(status,sort_order)`；产品列表使用 `(category_id,status,sort_order)` 与 `(status,is_featured,sort_order,published_at)`。

### 场景、案例与关系表

| 表/字段 | 类型 | 说明 |
|---|---|---|
| `application_scene.name/slug` | VARCHAR(100)，slug 唯一 | 场景名及 URL/前端 `key` |
| `slogan`、`summary` | VARCHAR(255/1000) | 首页场景卡文案 |
| `pain_point`、`solution` | TEXT | 行业痛点与方案概述 |
| `content_html` | LONGTEXT | 场景详细正文，写入时清洗 |
| `cover_media_id`、`is_featured`、`sort_order` | 关联/标记/排序 | 卡片呈现控制 |
| `status`、`seo_*`、`version`、`published_at` | 通用内容字段 | 场景公开状态和编辑控制 |
| `case_project.scene_id` | BIGINT，非空 | 所属场景；案例公开时场景也必须已发布 |
| `title`、`slug`、`client_name`、`location` | VARCHAR | 其中客户名、地点必须取得公开授权 |
| `summary`、`background`、`customer_need` | VARCHAR/TEXT | 卡片摘要、项目背景、客户需求 |
| `solution`、`implementation`、`result_summary` | TEXT | 方案、实施、结果；成果数据须确认授权 |
| `content_html`、`cover_media_id`、状态/SEO/版本字段 | 同上 | 详情、封面、发布与编辑控制 |

`product_scene_rel` 与 `product_case_rel` 均有内部主键 `id`、两个业务 ID 和 `sort_order`；各自的业务组合唯一，防止同一关系重复写入。查询案例按产品过滤时使用 `product_case_rel`，产品与场景的后台编辑使用 `product_scene_rel`。

## 索引、删除与数据一致性说明

1. 所有唯一索引与逻辑删除并存：逻辑删除后原 slug/username 仍占用；若要复用必须改旧数据或使用新标识。
2. 应用层会先校验关联对象存在；数据库目前没有 `FOREIGN KEY`，手工 SQL 导入必须自行保持关系正确。
3. 删除产品会删除其产品—场景关联；删除案例会删除其产品—案例关联；删除产品分类前服务层禁止仍有产品。
4. `cover_media_id` 删除/替换时要检查已发布内容引用，否则媒体公开访问会改变。
