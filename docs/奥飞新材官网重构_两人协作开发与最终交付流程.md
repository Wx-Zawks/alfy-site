# 奥飞新材官网重构：两人协作开发与最终交付流程

> 适用对象：两名借助 ChatGPT 进行 Vibe Coding 的新手开发者  
> 技术路线：Nuxt 3 + Vben Admin + Spring Boot 3 + MySQL 8 + 阿里云 ECS + Nginx

---

## 1. 总体协作原则

两个人最稳妥的协作方式是：

```text
主责分层 + 模块闭环 + Git 协作 + 互相审查 + 分阶段验收
```

| 角色 | 主责 | 辅责 |
|---|---|---|
| 同学 A：前端负责人 | Nuxt 官网、Vben 页面、移动端、SEO 展示 | 接口联调、内容整理 |
| 同学 B：后端负责人 | Spring Boot、MySQL、权限、上传、部署 | 页面审查、接口联调 |
| 共同负责 | 需求、接口约定、测试、上线、客户沟通 | 重要代码互审 |

核心原则：

1. 不要两个人分别开发两套完整系统。
2. 不要同时全面铺开官网、后台和后端。
3. 先完成一个完整业务闭环，再复制到其他模块。
4. 重要改动必须通过 Git 和 Pull Request。
5. ChatGPT 只辅助编码，不能代替测试、审查和文档。
6. 每周都要有一个可在测试环境演示的版本。

## 4. Git 协作规范

推荐分支：

```text
main
feature/xxx
fix/xxx
docs/xxx
```

标准流程：

```bash
git switch main
git pull
git switch -c feature/article-list

# 编写和测试代码

git add .
git commit -m "feat(article): add article list page"
git push -u origin feature/article-list
```

然后创建 Pull Request，由另一人检查后合并。

强制规则：

- 禁止直接向 `main` 推送；
- 一个分支只做一个小任务；
- 合并前另一人必须运行一次；
- 数据库变化必须带迁移脚本；
- 禁止提交 `.env`、密码、Webhook 和 API Key；
- 禁止通过微信压缩包覆盖代码；
- 禁止在生产服务器直接改源码；
- `main` 必须始终可运行。

分支示例：

```text
feature/article-api
feature/article-admin
feature/article-web
feature/product-upload
fix/article-slug-duplicate
docs/deployment-guide
```

## 5. 接口先约定，再编码

每个模块先在 `docs/api-contract.md` 中明确接口。

示例：

```text
GET /api/articles

参数：
- page
- size
- category
- keyword

返回：
{
  "code": 0,
  "message": "success",
  "data": {
    "records": [],
    "total": 0,
    "page": 1,
    "size": 10
  }
}
```

统一约定：

```text
时间：ISO 8601
成功 code：0
状态：draft / published / offline
分页：records / total / page / size
错误信息：message
空列表：[]
slug：唯一且不能为空
主键类型：全项目统一
```

协作顺序：

```text
确定字段
→ 编写接口文档
→ 前端用模拟数据开发
→ 后端实现接口
→ 前端接真实接口
→ 两人联调
```

## 6. ChatGPT / Vibe Coding 规范

不要一次让 AI 生成完整网站。每次只处理一个可验证的小任务。

推荐提示词结构：

```text
项目技术环境：
- Nuxt 3
- Vue 3
- TypeScript
- Spring Boot
- 不允许增加新的 UI 框架

当前任务：
实现新闻列表页面。

接口：
GET /api/articles?page=1&size=10

验收标准：
1. 支持分页；
2. 显示标题、封面、摘要和时间；
3. 有 loading；
4. 有空状态；
5. 有错误提示；
6. 点击进入 /news/[slug]；
7. 支持移动端；
8. 不修改无关模块。

请先列出修改文件和步骤，再给代码，最后给测试方法。
```

AI 生成代码后必须：

```text
自己阅读代码
确认未改无关文件
确认未写死地址和密码
运行 lint
运行类型检查
完成构建
手动测试
查看浏览器控制台
查看后端日志
由另一人审查
```

上线顺序：


- 页面标题和描述；
- 企业能否正常发布内容。

维护期内区分：

### 免费修复

已交付功能的缺陷，例如页面报错、上传异常和移动端严重错位。

### 新需求

英文站、新栏目、AI 客服、知识库、注册、订单系统或首页大改，需要另外评估。
