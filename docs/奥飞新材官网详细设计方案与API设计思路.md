# 奥飞新材官网详细设计方案与 API 设计思路

> 依据资料：`1 官网 - 思维导图.pdf`、`2 官网原型图设计.pdf`、7 月 11 日与 7 月 15 日沟通记录。  
> 一期目标：建设一个以品牌展示、产品与应用说明、案例背书、技术可信度和询盘转化为核心的企业官网，同时提供可由甲方自行维护内容的 CMS 后台。  
> 页面口径：下文的“10 个页面”指 10 种页面模板；产品、案例、新闻的实际内容条数不受模板数量限制。

---

## 1. 设计结论

### 1.1 官网定位

官网不是产品商城，也不是单纯的企业介绍页，而是：

```text
品牌可信度展示 + 气凝胶产品目录 + 行业应用方案 + 标杆案例背书 + 商务询盘入口
```

首页应让访客在 30 秒内理解五件事：

1. 奥飞新材是谁；
2. 与中南大学及粉末冶金全国重点实验室有什么关系；
3. 核心产品和核心技术是什么；
4. 产品可以解决哪些行业问题，是否已有落地案例；
5. 如何获取产品资料、项目方案或联系商务人员。

### 1.2 一期范围原则

- 以前台展示和后台内容管理为主；
- 不建设会员、订单、支付、客户门户；
- 不把实验室阶段技术写成已商业化能力；
- AI 助手只做接口和位置预留，是否上线单独评估 API 成本和知识库质量；
- 页面重图片、轻长文，首页突出已完成成果；
- PC 端保留原型图中的切换和横移动效，移动端自动降级为滑动卡片或纵向列表。

## 2. 信息架构与 10 个页面模板

### 2.1 一级导航

```text
首页｜产品｜应用与案例｜技术｜新闻｜合作｜我们｜获取方案
```

“获取方案”为高亮按钮，打开询盘弹窗或滚动到全站询盘组件。这样避免单独增加一个内容较薄的“联系我们”一级栏目。

### 2.2 页面清单

| 序号 | 页面模板 | 建议路由 | 主要作用 | 是否后台维护 |
|---:|---|---|---|---|
| 1 | 首页 | `/` | 品牌总览、核心内容导流、询盘转化 | 是 |
| 2 | 产品列表 | `/products` | 展示四大产品分类及全部产品 | 是 |
| 3 | 产品详情 | `/products/{slug}` | 展示卖点、参数、应用、关联案例 | 是 |
| 4 | 应用与案例 | `/applications` | 场景切换、案例筛选和列表 | 是 |
| 5 | 案例详情 | `/cases/{slug}` | 项目背景、方案、产品、效果和合作方 | 是 |
| 6 | 技术 | `/technology` | 气凝胶材料、复合产品及其他技术能力 | 是 |
| 7 | 新闻列表 | `/news` | 公司新闻、行业新闻分类浏览 | 是 |
| 8 | 新闻详情 | `/news/{slug}` | 正文、分享、相关推荐、SEO 落地 | 是 |
| 9 | 合作 | `/cooperation` | 经销商、复合产品开发、产业链合作 | 是 |
| 10 | 我们 | `/about` | 企业介绍、研发团队、招聘、联系信息 | 是 |

说明：

- “应用场景”和“案例”在同一页面中分别作为上半部分和下半部分呈现，案例仍有独立详情；
- “企业介绍、研发团队、招聘信息、联系我们”通过 `/about#company`、`/about#team`、`/about#jobs`、`/about#contact` 定位；
- 如果后期招聘内容增多，可把 `/about#jobs` 无损拆为 `/jobs`；
- 如果甲方坚持独立联系页，可新增 `/contact`，整体变为 11 个页面模板，不影响数据和 API 设计。

### 2.3 内容关系

```text
产品分类 1 ── N 产品
应用场景 N ── N 产品
应用场景 1 ── N 案例
案例 N ── N 产品
案例 N ── N 合作伙伴
新闻分类 1 ── N 新闻
```

关联关系非常重要。例如访客在“建筑节能”场景中，应能直接看到适用产品和三一云谷等案例；在产品详情中也应能反向看到应用场景和案例。

## 3. 首页详细设计

首页整体沿用原型图的长页叙事、红色强调、深蓝技术区、大图和不等宽卡片，但所有文案、图片、排序和跳转由后台配置。

### 3.1 顶部导航

- 初始状态可透明叠加在 Banner 上，向下滚动后切换为白底或深蓝底；
- Logo 左置，导航右置，“获取方案”使用红色实心按钮；
- 一级栏目不超过 7 个，产品可使用大菜单展示四类产品；
- PC 悬停展示二级菜单；移动端为抽屉菜单；
- 当前栏目高亮，所有链接有键盘焦点状态。

### 3.2 首屏 Banner

#### 内容

- 主标题：一句话表达公司能力或当前重点事件；
- 副标题：补充技术来源、产品方向和客户价值；
- 主按钮：查看产品/查看方案；
- 次按钮：获取项目方案；
- 背景：战略签约、研发实验、产品微观结构或实际项目视频/大图。

#### 交互

- 支持 1-3 张 Banner，不建议超过 3 张；
- 下方使用文字标题切换，不使用无含义的数字标号；
- 自动轮播 6-8 秒，鼠标悬停暂停；
- 文字切换与背景淡入同步；
- 移动端优先使用静态图片，关闭大体积背景视频。

#### 注意

当前原型图把战略签约作为首屏，后台应允许随市场重点更新，不能写死在前端。

### 3.3 四项信任背书

紧接 Banner 使用横向信息条：

| 模块 | 建议文案方向 |
|---|---|
| 技术来源 | 中南大学粉末冶金全国重点实验室 |
| 核心技术 | 新一代气凝胶常压干燥技术 |
| 客户验证 | 头部企业认可的可靠供应商 |
| 全链服务 | 从研发、复合开发到项目交付的完整闭环 |

每项包含短标题和一句说明，PC 四列，移动端两列。具体表述须经甲方和技术负责人审核后发布。

### 3.4 中南大学成果转化平台

#### 目标

突出“中南大学气凝胶成果转化核心平台”的身份，这是首页第一信任来源。

#### 版式

- 左侧：标签、两行大标题、80-120 字介绍、2 个按钮；
- 右侧：实验室/研究院实景大图；
- 下方可放 3-4 个经审核的数字指标，如研发年限、专利、博士/专家、合作项目；
- 不使用无法核实的夸大数据。

### 3.5 应用场景

#### 建议场景

```text
建筑节能、工业节能、石油石化、新能源汽车、通信机房、国防军工
```

以最终甲方确认的场景为准。缺少真实图片的场景暂不强行上线，可使用经授权的结构示意图，不能用与实际业务无关的图库图冒充案例。

#### PC 交互

- 上方为场景文字标签；
- 点击标签后，下方大图组向左滑动到对应场景；
- 当前场景用红色胶囊标签高亮；
- 主场景用 2/3 宽大卡片，次场景用 1/3 宽卡片；
- 图片上只放一句价值主张和“查看案例”，不堆积技术长文。

#### 移动端

- 改为横向可滑动的场景卡片；
- 不保留复杂联动位移动画；
- 默认显示 3-4 个场景，其余通过“查看更多”展开。

### 3.6 产品系列

#### 分类

依据思维导图建立四个一级分类：

1. 气凝胶粉体/分散体，约 5 个产品；
2. 气凝胶毡/板，约 5 个产品；
3. 气凝胶涂料相关配套，约 12 个产品；
4. 气凝胶涂料，约 6 个产品。

实际产品名称、数量和上下架状态由后台维护。

#### 版式

- 上方分类标签切换；
- 左侧大卡展示当前分类主推产品或系列卖点；
- 右侧 2×2 产品卡展示代表产品；
- 大卡可用施工/喷涂/材料应用图，产品卡尽量使用统一白底产品图；
- 卡片显示产品名、1 个核心卖点和详情入口；
- “查看全部”跳转到产品列表并携带分类参数。

### 3.7 标杆案例与合作伙伴

按照会议意见，将案例和合作伙伴上下联动，而不是做两个互不相关的 Logo 墙。

#### 案例区

- 顶部按应用领域切换；
- 左侧为置顶案例大图；
- 右侧为项目背景、使用产品、方案亮点和结果摘要；
- 下方 3 张案例卡；
- 鼠标悬停只做轻微放大和信息显现，不依赖悬停才能访问内容。

#### 合作伙伴区

- 展示已获得公开展示授权的客户/合作方 Logo；
- 点击 Logo 可筛选或跳转到相关案例；
- 没有公开案例的 Logo 不做虚假详情链接；
- Logo 使用统一灰度/彩色规则、统一安全边距。

### 3.8 技术能力

采用原型图中的深色整屏区，形成首页视觉节奏变化。

- 主叙事聚焦“新一代常压干燥技术”；
- 左侧为技术定位、简述和详情按钮；
- 右侧为 4-6 条已验证指标或技术特点；
- 下方三张技术卡：气凝胶材料技术、气凝胶复合产品技术、其他技术；
- 已产业化能力与实验室储备能力在标签和文案上明确区分；
- 数据、认证和性能指标必须注明测试口径或来源，避免营销表述超出证据。

### 3.9 新闻

采用“核心新闻置顶 + 次要新闻右侧列表”的不等宽布局：

- 左侧：1 篇带大图或视频的置顶新闻；
- 中间：1 篇红色重点卡；
- 右侧：3-4 篇紧凑新闻；
- 显示分类、日期、标题，不在首页放长摘要；
- 后台分别控制 `isFeatured` 和 `sortOrder`；
- 公司新闻和行业新闻可切换，默认公司新闻。

### 3.10 询盘与页脚

询盘模块与页脚合并：

- 标题：“获取产品资料或项目方案”；
- 字段：姓名、手机、公司、需求类型、需求描述、隐私同意；
- 联系电话、邮箱、地址、企业微信二维码；
- 快速导航、产品分类、备案号、版权信息、隐私政策；
- 提交成功后生成询盘编号，并可选推送企业微信；
- 不把客服电话、手机号、邮箱写死在页面代码中。

## 4. 内页详细设计

### 4.1 产品列表页

页面结构：

```text
栏目头图/简介
四类产品标签
产品网格
应用入口
获取方案 CTA
```

- 默认展示全部产品，支持分类筛选和 URL 参数 `/products?category=coating`；
- 卡片字段：图片、产品名称、短描述、2-3 个特点、详情入口；
- 后台可设置主推、排序、上下架；
- 一期产品数量不多时不做复杂搜索；超过 30 个产品后再加关键词和参数筛选。

### 4.2 产品详情页

页面结构：

```text
面包屑
产品主图/图集 + 产品名称 + 一句话价值 + 咨询按钮
核心特点
技术参数表
应用领域
施工/使用说明或注意事项
相关案例
相关产品
资料获取 CTA
```

设计要求：

- 参数使用标准表格，不把参数做成不可检索的图片；
- 可公开下载的手册由后台上传 PDF；涉及敏感资料时改为留资后人工发送；
- 产品图统一比例，建议 4:3 或 1:1；
- 详情正文支持富文本，但前端限定标题、段落、表格、图片等安全样式；
- 每个产品有独立 SEO 标题、描述和可读 slug。

### 4.3 应用与案例页

页面分两段：

1. 应用场景：大图标签切换，一句话说明行业痛点、奥飞方案、推荐产品；
2. 案例中心：按场景、产品筛选案例卡片。

卡片字段：案例名称、场景、地点（可选）、使用产品、封面图、结果摘要。无真实项目数据时只展示“应用场景”，不伪造案例。

### 4.4 案例详情页

页面结构：

```text
项目主视觉
项目概况
客户需求/行业痛点
采用的产品与方案
实施过程
项目结果/数据
项目图片或视频
合作伙伴
相关产品与场景
咨询 CTA
```

所有节能率、温差、厚度、防火等级等数字应保留检测或项目来源字段，后台可记录但前台可按授权决定是否展示。

### 4.5 技术页

页面结构：

- 技术总览；
- 气凝胶材料技术；
- 气凝胶复合产品技术；
- 其他技术/技术储备；
- 研发平台与团队；
- 专利、论文、检测和资质；
- 合作机构；
- 技术咨询 CTA。

后台用“内容区块”维护，支持图文、指标、证书、时间线和技术卡片。页面必须区分“已量产”“中试/验证中”“实验室储备”。

### 4.6 新闻列表与详情

列表：

- 公司新闻、行业新闻两个主分类；技术文章可作为后续分类；
- 一篇置顶新闻使用大卡，其余使用列表/网格；
- 支持分类、分页、年份筛选；
- URL 保留筛选状态。

详情：

- 标题、分类、日期、来源、封面、正文；
- 图片说明、视频、附件；
- 上一篇/下一篇和 3 篇相关推荐；
- 分享按钮只做链接生成，不强依赖第三方脚本；
- Article 结构化数据、Open Graph 信息由服务端渲染。

### 4.7 合作页

根据思维导图设置三类合作：

1. 经销商合作；
2. 复合产品开发模式；
3. 产业链合作模式。

每类包含合作对象、可提供能力、合作流程、基本条件、案例/伙伴和“申请合作”表单。合作模式尚未最终确定前，可先发布概览和联系入口，不写具体承诺。

### 4.8 我们页

页面通过吸顶锚点导航组织：

```text
企业介绍｜发展历程｜研发团队｜资质荣誉｜招聘信息｜联系我们
```

- 企业介绍：定位、历史、文化、生产/研发能力；
- 研发团队：照片、姓名/职务、公开简介，是否公开由本人和甲方确认；
- 招聘：岗位、地点、职责、要求、状态、投递方式；
- 联系：地址、电话、邮箱、地图、二维码和询盘表单；
- 地图优先使用高德/百度合规组件，加载前显示隐私提示或静态地图占位。

## 5. 视觉与交互规范

### 5.1 视觉关键词

```text
专业、可信、科技、材料感、简洁、产业化、开放合作
```

### 5.2 色彩建议

以下为设计阶段建议值，最终应从正式 Logo/VI 取色：

| 用途 | 建议色 |
|---|---|
| 品牌强调/按钮 | 红色 `#E31B23` |
| 深色科技区 | 深蓝 `#063B55` 或 `#0E2538` |
| 主文字 | `#171A1F` |
| 次文字 | `#606874` |
| 浅背景 | `#F5F6F7` |
| 分割线 | `#E5E7EB` |

红色只用于主按钮、当前标签和重点信息；深蓝用于技术、页头或大面积品牌场景，避免全站高饱和红色造成压迫。

### 5.3 排版和栅格

- PC 内容最大宽度建议 1200-1280px；
- 设计基准宽度 1440px；
- 区块上下间距 96-128px，移动端 56-72px；
- 中文字体使用系统无衬线字体栈，数字可搭配 Inter/DIN 类字体；
- 标题短而有力，首页单个模块正文尽量不超过 120 字；
- 图片先于长文，重点通过卡片面积差而非大量装饰表达。

### 5.4 动效原则

- 首屏淡入、标题分行进入、卡片轻微上浮；
- 应用场景点击后横向位移；
- 产品分类淡入/交叉切换；
- 数字在进入视口时计数一次；
- 动效时长 200-600ms，不使用大幅旋转和高频视差；
- 支持 `prefers-reduced-motion`；
- 移动端关闭视频自动播放、复杂位移和悬停专属交互。

### 5.5 素材规格

| 素材 | 建议规格 |
|---|---|
| 首页 Banner | 1920×900，WebP/AVIF，单张建议小于 500KB |
| 场景大图 | 1600×900，16:9 |
| 案例封面 | 1200×800，3:2 |
| 产品图 | 1200×1200 或 1200×900，背景风格统一 |
| 新闻封面 | 1200×675，16:9 |
| 团队头像 | 800×1000，4:5 |
| 合作伙伴 Logo | SVG 优先，或透明 PNG |

后台上传原图后生成多尺寸缩略图，并输出 WebP；前端使用响应式图片和懒加载。

## 6. 技术架构建议

### 6.1 推荐架构

```text
访客
  ↓ HTTPS
Nginx/CDN
  ├─ www.alfy.com.cn   Nuxt 3 官网（SSR/混合渲染）
  ├─ admin.alfy.com.cn Vben Admin 内容后台
  └─ api.alfy.com.cn   Spring Boot 3 REST API
                           ├─ MySQL 8
                           ├─ OSS/本地文件存储
                           └─ 企业微信 Webhook（可选）
```

推荐技术：

- 官网：Nuxt 3、Vue 3、TypeScript；
- 后台：Vben Admin Element Plus 版本；
- API：Spring Boot 3、JDK 17、MyBatis Plus；
- 数据库：MySQL 8；
- 鉴权：Spring Security 或 Sa-Token，二选一；
- 文档：OpenAPI 3 + Knife4j/Swagger UI；
- 部署：阿里云 ECS + Nginx，一期可选 RDS 和 OSS；
- 统计：百度统计、百度搜索资源平台，可选 Google Search Console。

### 6.2 为什么需要服务端渲染

产品、案例和新闻是主要搜索入口。Nuxt SSR/混合渲染可以在首个 HTML 中输出标题、摘要、正文和结构化数据，便于搜索引擎抓取，也改善首屏体验。

### 6.3 不建议一期微服务化

内容量和并发量不足以支撑微服务成本。一期用一个 Spring Boot 服务按业务模块分包即可，后续 AI、搜索或文件处理确有独立扩容需求时再拆分。

## 7. API 总体设计

### 7.1 基本约定

```text
Base URL: https://api.alfy.com.cn/api/v1
协议: HTTPS + JSON
字符集: UTF-8
公开读取接口: 无需登录
后台接口: /api/v1/admin/**，必须登录并校验权限
时间格式: ISO 8601，例如 2026-07-16T10:30:00+08:00
ID: 后端使用 BIGINT，JSON 中建议按字符串返回，避免前端精度问题
```

统一响应：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "requestId": "01J..."
}
```

分页响应：

```json
{
  "code": "OK",
  "message": "success",
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 12,
    "total": 35,
    "totalPages": 3
  },
  "requestId": "01J..."
```

常用错误码：

| HTTP | 业务码 | 场景 |
|---:|---|---|
| 400 | `VALIDATION_ERROR` | 字段校验失败 |
| 401 | `UNAUTHORIZED` | 未登录或登录过期 |
| 403 | `FORBIDDEN` | 无操作权限 |
| 404 | `CONTENT_NOT_FOUND` | 内容不存在或未发布 |
| 409 | `SLUG_CONFLICT` | slug 重复 |
| 409 | `VERSION_CONFLICT` | 内容被其他管理员修改 |
| 429 | `RATE_LIMITED` | 询盘或登录请求过频 |
| 500 | `INTERNAL_ERROR` | 服务异常 |

### 7.5 内容状态和发布流程

```text
DRAFT 草稿 → PUBLISHED 已发布 → OFFLINE 已下线
```

- 内容管理员可新建、编辑和提交发布；
- 一期若不做审核流，可授权内容管理员直接发布；
- 如果甲方需要审核，在不改表结构的前提下增加 `PENDING_REVIEW`；
- 发布接口校验必填字段、slug、封面、SEO 和关联数据；
- 所有发布、下线、删除、恢复动作记入操作日志；
- 使用 `version` 字段做乐观锁，防止多人编辑相互覆盖。

### 7.6 预览方案

草稿不能通过公开详情 API 访问。后台点击预览时生成 10 分钟有效的签名预览链接：

```text
https://www.alfy.com.cn/preview/products/aerogel-coating?token=...
```

Nuxt 服务端带 token 调用预览接口，token 仅能读取指定内容，过期后自动失效。

## 10. SEO、性能与安全

### 10.1 SEO

- 每个产品、案例、新闻具有独立 title、description、slug、canonical；
- Nuxt 服务端输出 H1、正文和结构化数据；
- 产品使用 `Product`，新闻使用 `Article/NewsArticle`，公司信息使用 `Organization`；
- 自动生成 `/sitemap.xml` 和 `/robots.txt`；
- 后台、API、预览页禁止收录；
- `alfy.cn` 和 `www.alfy.cn` 保留路径 301 到 `www.alfy.com.cn`；
- 上线前整理旧站 URL 映射，不能把所有旧链接粗暴跳转到首页；
- 图片必须有可编辑 alt；
- 新闻日期、作者/来源保持真实。

### 10.2 性能

- 首页聚合接口缓存 60-300 秒；内容详情缓存 5-30 分钟；发布后清缓存；
- 图片生成多尺寸 WebP/AVIF，首屏图预加载，其余懒加载；
- Banner 视频提供封面图，移动端不自动下载；
- 静态资源使用长缓存和文件指纹；
- 目标：移动网络下核心内容可快速出现，LCP 尽量小于 2.5 秒，CLS 小于 0.1；
- 第三方统计、地图、聊天组件延迟加载。

### 10.3 安全

- 后台登录验证码、失败次数限制、强密码、token 过期；
- refresh token 使用 Secure、HttpOnly、SameSite Cookie，访问 token 短时有效；
- 后台接口进行 RBAC 校验，不能只靠前端隐藏按钮；
- 富文本服务端清洗，防止 XSS；
- 文件同时校验扩展名、MIME 和文件头，重命名存储，上传目录禁止执行；
- 询盘接口按 IP/设备限流，启用验证码、隐藏蜜罐字段和重复手机号检测；
- 联系信息属于个人信息，提供隐私政策、用途说明和保存期限；
- 数据库、8080 等内部端口不得暴露公网；
- 操作日志不得记录密码、token、Webhook、完整敏感配置。
