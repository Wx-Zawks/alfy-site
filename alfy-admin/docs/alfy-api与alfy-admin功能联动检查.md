# alfy-api 与 alfy-admin 功能联动检查

检查日期：2026-07-22

## 1. 结论

`alfy-api` 已覆盖内容管理的主体能力，但没有完整覆盖原 `alfy-admin` 中展示的所有功能。

本次已把 `alfy-admin/apps/web-ele` 从浏览器 `localStorage` 演示数据切换为真实的 `alfy-api` 接口，并完成登录、内容、首页、媒体、询盘、SEO、站点结构及站点设置等已有接口的联动。后端尚未提供的功能没有继续伪造成功数据，前端改为明确提示，缺口记录在本文第 4 节。

## 3. 前端主要改动

- 开发环境 API 基址改为 `/api/v1`，Vite 将 `/api` 代理到 `http://localhost:8080`，关闭 Nitro Mock。
- 重写认证接口和令牌刷新逻辑，保存后端返回的 Refresh Token。
- 增加统一 CMS API 层和后端/前端数据适配层。
- 内容管理、首页配置、询盘、媒体、SEO、系统设置及仪表盘移除 `localStorage` 模拟数据。
- 新增产品分类管理和站点结构管理页面。
- 编辑请求携带后端 `version` 字段，保留乐观锁语义。
- 媒体文件接口需要 Bearer Token，前端使用认证请求读取 Blob，避免 `<img>` 标签无法添加请求头的问题。

## 4. 未完成或存在问题的功能

### P0：空数据库没有管理员，暂时不能登录后台

当前数据库表已创建，但 `admin_user` 为空。后端只会在管理员表为空且同时提供以下环境变量时创建第一个超级管理员：

```powershell
$env:ALFY_INITIAL_ADMIN_USERNAME = "admin"
$env:ALFY_INITIAL_ADMIN_PASSWORD = "请设置一个后台登录密码"
.\mvnw.cmd spring-boot:run
```

这不是数据库密码。MySQL 密码 `1234` 只用于后端连接数据库，不能用于后台登录。

影响：本次可以完成静态契约检查、类型检查和生产构建，但无法完成“真实登录后逐项增删改查”的端到端验收。

### P1：文章分类只有公共查询接口，没有后台维护接口

后端没有文章分类的管理员新增、修改、删除接口。当前迁移已初始化 6 个默认文章分类，文章可以使用这些分类创建；但分类名称、层级、启停和排序都不能在后台维护。如果默认分类被清空，后台也无法自行恢复，而文章请求必须提供分类 ID。

建议：增加 `/api/v1/admin/article-categories` 的列表、详情、新增、修改、删除和排序接口。

### P1：媒体缺少修改和删除接口

后端仅支持媒体列表、上传和读取文件，没有修改 `altText`、替换文件或删除媒体的接口。因此前端媒体页只能上传/查看，不能真正执行原界面中的编辑和删除。

建议：增加 `PUT /api/v1/admin/media/{id}` 和安全删除接口；删除时校验是否被文章、产品、页面等内容引用。

### P1：管理员、角色和权限管理未实现

`admin_user` 表和认证已存在，但没有管理员列表、创建、禁用、重置密码或角色分配接口。原系统设置页展示的用户管理目前只能显示“后端未提供接口”。

同时，安全配置只允许 `SUPER_ADMIN` 和 `CONTENT_ADMIN` 访问全部 `/api/v1/admin/**`。原前端概念中的 `inquiry_admin` 没有对应后端授权模型，权限码接口也固定返回 `CMS_READ`、`CMS_WRITE`。

建议：补充管理员与角色接口，并按文章、媒体、询盘、系统设置等资源细分权限。

### P1：操作日志只能写入，不能查询

后端已有 `admin_operation_log` 表和记录服务，但没有后台日志列表/详情接口。前端系统设置页因此无法展示真实操作日志。

建议：增加分页查询接口，并支持操作人、资源类型、动作和时间范围筛选。

### P1：首页案例的数据模型不足

案例只有 `featured` 和 `sortOrder`，没有独立的 `showOnHome`、`homePinned`、`homeSortOrder`，也没有数据库约束保证“只能有一个主推荐”。目前前端把首页推荐映射到 `featured`，排序映射到全局 `sortOrder`。

影响：案例列表排序与首页排序互相耦合，多管理员同时操作时也可能产生多个推荐案例。

建议：为案例增加独立首页投放字段，或建立首页案例关联表，并由后端事务保证唯一主推荐。

### P2：没有 404/访问统计接口

SEO 页原有“404 监控”没有后端数据源，仪表盘也没有独立统计接口。当前 404 表显示为空，仪表盘仅对最多 100 条列表结果做前端聚合。

建议：增加访问统计和 404 事件上报/查询接口。

### P2：部分响应缺少关联 ID，前端只能从 URL 或树结构反推

- Banner、页面 Hero、站点设置响应返回媒体 URL，但不返回原始媒体 ID；前端目前从 `/media/{id}` 形式的 URL 解析 ID。
- 导航响应没有 `parentId`；前端从嵌套树的父子关系反推。

影响：如果媒体 URL 格式或导航响应结构变化，编辑回显会失效。

建议：管理员响应 DTO 同时返回 `desktopMediaId`、`mobileMediaId`、`logoMediaId`、`parentId` 等原始关联字段。

### P2：前端列表暂按最多 100 条加载

后端分页接口的单页上限是 100。本次为了兼容现有无分页页面，内容、询盘和媒体暂请求 `size=100`。数据超过 100 条后不会显示全部记录，仪表盘统计也会偏小。

建议：为各管理页面增加真正的服务端分页，或提供专门的统计接口。

### P2：生产 API 地址需要部署时确认

生产环境当前配置为 `https://api.alfy.com.cn/api/v1`。部署前需确认真实域名、HTTPS 证书、CORS 和反向代理配置。

### P2：Refresh Token 存储安全可继续加强

后端把 Refresh Token 返回在 JSON 中，前端只能存入浏览器存储。若页面出现 XSS，令牌可能被读取。

建议：生产环境改用 `HttpOnly + Secure + SameSite` Cookie 保存 Refresh Token，并配合 CSRF 策略。

### P2：Flyway 版本尚未声明支持 MySQL 8.4

后端测试和迁移均成功，但 Flyway 输出警告：当前版本只测试到 MySQL 8.1，而本机是 MySQL 8.4。

建议：升级 Flyway/MySQL 数据库模块到明确支持 MySQL 8.4 的版本，并在升级后重新执行迁移验证。

## 5. 验证结果

- `pnpm run build:alfy`：通过，Vite 成功构建 4956 个模块。
- `mvn test`：通过，共 7 个测试，0 失败、0 错误；同时成功连接 `alfy_site_dev` 并验证 15 个 Flyway 迁移。
- `vue-tsc --noEmit --skipLibCheck`：本次修改的 `apps/web-ele` 未产生类型错误；命令仍因仓库原有 Vben 公共包错误退出，涉及 `popup-ui`、`common-ui`、`layouts` 和 `vxe-table`。
- `git diff --check`：通过，无空白字符错误。
- ESLint 业务规则检查：通过。完整 ESLint 与 Prettier 在本仓库部分 Vue 模板换行规则上存在循环修复冲突，另有 `vite.config.mjs` 原有依赖声明告警。
- 数据库复核：`admin_user` 为 0 条，`article_category` 为 6 条。
- 真实登录态接口验收：未执行，原因是空数据库尚无管理员账号。

## 6. 建议验收顺序

1. 使用环境变量创建首个后台管理员并启动 `alfy-api`。
2. 启动 `alfy-admin`，验证登录、令牌刷新和退出。
3. 先上传媒体、创建产品分类，再验证产品、场景、案例及首页配置。
4. 后端补齐文章分类管理后再验收文章新增。
5. 验证询盘状态流转、跳转规则、导航、页面 Hero 和站点设置。
6. 最后补齐媒体管理、管理员/角色、操作日志和统计类接口。
